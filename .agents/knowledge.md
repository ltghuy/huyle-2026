# Project Knowledge

Cross-feature decisions, gotchas, and codebase discoveries. Owned by spec-driven.

Entries are grouped by scope: `repo` (workspace, tooling, deploy), `web` (the portfolio, `apps/web`), `react-handbook` (`apps/react-handbook`; paths in its entries are relative to that app), `learn-english` (`apps/learn-english`, planned; paths relative to that app).

## Decisions

### repo

- **[004] Monorepo deploys keep Workers Builds root at `/` and call `cf:*` root
  scripts** that delegate with `pnpm --filter web`. Roll out in two phases (stable
  script names first, then the move) because a push to `main` auto-deploys.
  Deploy/preview bypass turbo (uncacheable; strict env mode strips Cloudflare vars).
- A dependency used by two or more workspace packages takes its version from the
  default `catalog` in `pnpm-workspace.yaml` and is listed as `"catalog:"` in each
  package.json; a dependency only one package uses keeps its own range. To bump a
  shared package, change the catalog and run `pnpm install`. `catalogMode: prefer`
  makes `pnpm add` write `catalog:` for packages already in the catalog -- the apps
  had drifted apart (web on next 16.3.0, the others on 16.3.8) <!-- quick:003 date:2026-10-28 -->

## Gotchas

### repo

- **`pnpm deploy` is a pnpm built-in** — it never runs a `deploy` script. Use
  `pnpm run deploy`, or name the script so it can't collide (this repo: `cf:deploy`).
- **Turborepo strict env mode hides undeclared env vars.** Any env var read during
  `next build` (today `GOOGLE_SITE_VERIFICATION`) must be in the `build` task's
  `env` in `turbo.json`, or the build silently renders without it.
- **Some packages must have ONE version across the pnpm workspace.** [005]
  - `@types/react`: pnpm publicly hoists `*types*`; with two versions, the
    portfolio type-checked against the hoisted copy while R3F augments its own →
    `'group' does not exist on type 'JSX.IntrinsicElements'`. Keep one version
    (both are in the pnpm catalog, quick 003).
  - Playwright: playwright-bdd imports `playwright` without declaring it and gets
    pnpm's hoisted copy; a second Playwright version makes it read the wrong
    internals → `bddTestData not found` (full-suite runs only). Keep
    `@playwright/test` on one exact version in the catalog.
- **`pnpm add <pkg>@catalog:` rewrites `pnpm-workspace.yaml`**: it sorts the
  catalog alphabetically and moves the comments, so the grouping is lost. Add the
  entry to the catalog by hand and run `pnpm install` instead (quick 003, feature
  learn-english 005). <!-- feature:005 date:2026-10-28 -->
- **`.claude/rules` frontmatter: only `paths:` is read.** Any other key (this repo
  used `appliesTo:`) is ignored without an error, so the rule silently loads for
  every file. Verified in the Claude Code memory docs (2026-10-26, feature 005).
- **Path-scoped agent rules break on moves.** `.claude/rules/*.md` `paths:` globs
  are repo-relative; moving source (e.g. into `apps/web/`) silently stops the rule
  from activating unless the globs move too.
- **Shared UI package + Tailwind v4:** classes used only inside a workspace package
  are not scanned unless the app CSS adds `@source "<path to package>"`.
- **`pnpm start` is also a pnpm built-in** (falls back to `node server.js` when the
  package has no `start` script). The root manifest forwards `start` and
  `test:watch` to `apps/web` for that reason; add a forwarder for any other
  app-only script that should work from the root.
- **Shared config packages must declare their peers as devDependencies too.**
  pnpm doesn't link a peer into the package's own `node_modules`, so
  `@repo/eslint-config` importing `eslint/config` failed with ERR_MODULE_NOT_FOUND
  until `eslint` was added as a devDependency next to the peer.
- **A `next/font/google` failure can poison the Turbopack cache.** The first build
  after the move failed with "Can't resolve '@vercel/turbopack-next/internal/font/google/font'
  … next/font/google queries have exactly one entry"; every rebuild repeated it
  until `apps/web/.next` was deleted, then it never recurred. Likely a transient
  Google Fonts fetch failure cached in `.next/cache`. Fix: `rm -rf apps/web/.next`.
- **A green Workers Builds run proves nothing about settings you asked for.**
  [004] T002 was marked done on a green deploy, but the dashboard still ran
  `npx opennextjs-cloudflare build`, which only works with the app at the repo
  root. The move then failed in CI ("npm error could not determine executable to
  run"). Before a structural push, confirm the build log's
  `Executing user build command:` line matches the intended command.
- **Playwright `reuseExistingServer: true` will test whatever is on :3000**,
  including a stale dev server from an old layout or an earlier run. Check
  `lsof -ti :3000 -sTCP:LISTEN` before trusting an e2e pass after structural moves.
- **AGENTS.md is regenerated by `next dev`.** It warns Next 16 has breaking changes;
  read `node_modules/next/dist/docs/` before writing Next code. Committing the block
  with your work keeps the tree clean.
