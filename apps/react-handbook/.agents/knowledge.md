## Decisions

- shadcn/ui with the `base-nova` style (Base UI primitives, not Radix) is the only UI component library -- it's the current shadcn CLI default; one library keeps a11y behavior and theming consistent <!-- feature:000 date:2026-10-06 -->
- Business logic lives in `src/server/*` services guarded by `server-only`; route handlers and Server Actions are thin adapters over them -- same logic serves HTTP consumers and the UI without an internal HTTP hop <!-- feature:000 date:2026-10-06 -->
- Zod for every trust boundary (request bodies, env vars) -- types and runtime validation come from one schema <!-- feature:000 date:2026-10-06 -->
- Practice features (002–015) hand-build their core logic with no third-party runtime libraries; basic shadcn primitives (Button, Input, Card) are allowed for styling, but shadcn's version of the practiced pattern (Dialog, Toast, Accordion…) is never used in that practice -- the point is to practice the hard part <!-- feature:001 date:2026-10-06 -->
- Practice demo data comes from this repo's own mock API routes (generated data, configurable latency + error injection); chat uses SSE + POST; uploads hit a real endpoint for real progress -- real network behavior without external dependencies <!-- feature:001 date:2026-10-06 -->
- Every practice page = title/summary, explanation panel, optional demo controls, live demo; one URL per practice -- consistent frame, refresh-safe, per-practice code loading <!-- feature:001 date:2026-10-06 -->
- The toast service from practice 002 is the playground's app-wide notification system: other practices raise toasts with the `toast` API from `src/practices/toast-notifications/toast-store.ts`; `<Toaster />` is mounted once in the playground layout (the one intended shell exception) <!-- feature:002 date:2026-10-06 -->
- Accordion panels use `aria-labelledby` without `role="region"` when many panels can be open (APG warns about landmark proliferation above ~6) <!-- feature:003 date:2026-10-06 -->
- Long-lived mock server state with timers (chat room, simulated participants) lives on `globalThis` so dev HMR doesn't duplicate timers and every route module in the process shares it; the stream is SSE from a route handler (`ReadableStream`), read on the client with `fetch` + a hand-built parser instead of `EventSource` so reconnect/backoff is practiced, not hidden <!-- feature:006 date:2026-10-07 -->
- Every practice's "How it works" panel is a guide built from `src/components/playground/practice-guide.tsx`: always-visible What it is + Key ideas, then `ReadMore` with Where you'd use it, How we built it, Best practices, Try it with the demo controls, Trade-offs and limits. Content comes from that feature's spec/decisions/design/audit (SSOT); new practices write their guide in this shape <!-- quick:002 date:2026-10-07 -->
- Virtualized lists in the playground use the framework-free `Virtualizer` (`src/practices/virtualized-list/virtualizer.ts`): sizes by item key in a Fenwick tree, anchor-based scroll correction in a layout effect followed by a synchronous `useSyncExternalStore` notification, reveal targets that persist until the user scrolls, and a pinned focusable row (roving tabindex). Practices 13/14 can reuse it instead of re-deriving the math <!-- feature:008 date:2026-10-07 -->
- The playground's shared modal is `<Modal>` (controlled: `open` + `onRequestClose(reason)`) and `await confirm()` from `src/practices/accessible-modal/`; `<ModalHost />` is mounted once in the playground layout (second intended shell exception after the toaster). Anything that must stay usable above an open dialog gets `data-modal-keep` (the toaster has it); do not use shadcn Dialog/Sheet for new dialogs <!-- feature:009 date:2026-10-07 -->
- Shared client state pattern for later practices: a pure reducer with a typed action union + exhaustive `never` check, shared through a store in context and `useShopSelector`-style hooks (`useSyncExternalStore` + memoized, equality-checked selection); see `src/practices/context-reducer/shop-context.tsx`. Avoid a single context holding `{ state, dispatch }` for widely read state <!-- feature:010 date:2026-10-07 -->
- Demos that compare loading strategies count requests on the server, keyed by a per-run id carried in every URL (requests, bytes, failures, cancellations via `request.signal`), and push the numbers over SSE; the page can't see native/eager fetches or cancelled ones. Per-run latency/failure live on the server so changing them doesn't change URLs (and re-request `<img>`s); see `src/server/practices/lazy-images/` <!-- feature:012 date:2026-10-08 -->
- Input-driven requests in the playground (search, filters) use the run-id pattern from `src/practices/debounced-search/search-engine.ts`: every search start increments a run id and a response may update the screen only if its run id is current; `AbortController` is added to save work, never relied on for correctness. Query text is normalized with the shared `normalizeQuery` (client and server) before it becomes a cache key <!-- feature:013 date:2026-10-08 -->
- The site is the Frontend Handbook (renamed from "Frontend Interview Handbook" in quick 005): content is grouped into sections listed in `sections` (`src/practices/catalog.ts`), each with its own URL prefix and sidebar folder. React Practices (`/react-practices`, the 14 practices) is the first; a new section adds its entry there (href set once it has content), a route folder under `src/app/(playground)/{section}/`, and a sidebar folder. Practice code stays in `src/practices/*` and APIs under `/api/practices/*` <!-- quick:004 date:2026-10-08 -->
- Tabular practices reuse the data grid from feature 014: one pure, client-safe query (`queryEmployees` in `src/server/practices/data-grid/grid.query.ts`: filter → stable multi-key sort with `Intl.Collator` numeric/base, empty last, id tiebreak → clamped page) shared by browser and mock API, an id-based selection with an "all matching = filter key + exceptions" rule (`src/practices/data-grid/selection.ts`), and the `GridController` (browser/server modes, run-id guard). Practice 14 (large datasets) should start from it rather than re-deriving sorting/filtering <!-- feature:014 date:2026-10-08 -->
- Performance practices measure outside React: a module-level metrics store (`src/practices/large-dataset/metrics.ts`) times each update from its trigger (event, feed update, or a component starting a render on its own) to the first layout effect after the commit, counts row renders, and is read by its panel on a 250 ms timer, so measuring never re-renders what it measures <!-- feature:015 date:2026-10-08 -->

## Gotchas

- `next dev` rewrites the managed block in `AGENTS.md`; put project instructions in `CLAUDE.md` / `.claude/rules/`, not in `AGENTS.md` -- edits there get reverted <!-- feature:000 date:2026-10-06 -->
- shadcn `base-nova` components are built on Base UI, so Radix-specific props/examples (e.g. `asChild`) may not apply -- check the generated component source before copying docs examples <!-- feature:000 date:2026-10-06 -->
- Next 16 `error.tsx` and `catchError` fallbacks get `retry()` (re-fetch + re-render), not the old `reset()` -- training-data examples using `reset` are outdated; `catchError` from `next/error` is the component-level boundary <!-- feature:001 date:2026-10-06 -->
- shadcn init left dark mode class-based (`.dark`) with nothing setting the class, and `--font-sans: var(--font-sans)` self-referencing -- dark mode never activated and Geist never applied until fixed in 001 <!-- feature:001 date:2026-10-06 -->
- Theme is class-based again (quick task 001-theme-toggle): `.dark` on `<html>` is set by an inline `<head>` script from `localStorage.theme` (absent = system) before paint; `<html>` has `suppressHydrationWarning`. Use `dark:` variants as usual; never read the theme during server render <!-- quick:001 date:2026-10-06 -->
- Run accessibility audits in **both** themes: headless Chrome reports a dark OS, so light-mode contrast bugs (muted text on muted backgrounds, ~4.34:1) went unnoticed until the theme toggle existed. Avoid `text-muted-foreground` on `bg-muted`/`bg-accent`; use `text-foreground/75` <!-- quick:001 date:2026-10-06 -->
- Toggle handlers that cycle a value must read the live value at click time, not the rendered one: rapid clicks can land before React re-renders <!-- quick:001 date:2026-10-06 -->
- Turbopack (Next 16.3): server-side `import()` maps don't code-split client components. Every client chunk reachable from a page's module graph is emitted as a `<script>` for that page, and a layout importing the map pulls them into every page. Use separate route files (or client `next/dynamic`) for per-feature splitting <!-- feature:001 date:2026-10-06 -->
- The shadcn-generated `use-mobile.ts` fails the React Compiler lint rule `react-hooks/set-state-in-effect`; it was rewritten with `useSyncExternalStore` -- re-apply if the sidebar is ever re-added with `--overwrite` <!-- feature:001 date:2026-10-06 -->
- `pkill -f "next start"` doesn't match the running process (it renames itself `next-server`); stop test servers by port (`lsof -tiTCP:PORT -sTCP:LISTEN | xargs kill`) or stale builds get served <!-- feature:001 date:2026-10-06 -->
- Deleting or moving route/module files while `next dev` (Turbopack) runs can leave a stale module graph: "Module ... was instantiated ... but the module factory is not available". Restart dev with `rm -rf .next && pnpm dev`; only one `next dev` per project is allowed, so verify structural changes with `pnpm build && pnpm start` on another port <!-- feature:001 date:2026-10-06 -->
- shadcn neutral `--ring`/`--sidebar-ring` in light mode (L 0.708) gives only ~2:1 focus-ring contrast on near-white surfaces (WCAG needs 3:1); the sidebar ring was darkened to 0.556. Check ring contrast for any new focusable surface <!-- feature:001 date:2026-10-06 -->
- Headless Chrome doesn't apply `:focus-visible` to scripted `.focus()`; verify focus rings by computed tokens/contrast or with a real Tab key press <!-- feature:001 date:2026-10-06 -->
- Puppeteer screenshots call `setViewport`; if the page was opened with `isMobile`/`hasTouch`, that change reloads the page and wipes client state (e.g. the toast store). Test narrow layouts with a plain 360 px `defaultViewport` instead <!-- feature:002 date:2026-10-06 -->
- Accent-insensitive search must fold per character and keep an index map back to the original string; folding the whole string first breaks highlight positions because NFD and lowercasing can change length <!-- feature:003 date:2026-10-06 -->
- React applies updates from click handlers in a microtask: tests that call `el.click()` must `await` before reading the DOM, and wait a tick before polling after an action that resets UI (otherwise they read the old DOM) <!-- feature:005 date:2026-10-07 -->
- The playground's shared data layer is `useQuery` / `queryClient` in `src/practices/data-fetching-hook/` (module-level cache, survives navigation); later practices may use it, except practice 12 <!-- feature:005 date:2026-10-07 -->
- `sessionStorage` is copied into tabs opened with `window.open` or duplicated, so a per-tab id persisted at load time is shared by two open tabs; give each page load a fresh id and persist history only on `pagehide` (see chat `identity.ts`) <!-- feature:006 date:2026-10-07 -->
- When the server assigns order on arrival (chat `seq`), parallel optimistic sends with different latencies overtake each other; send through a serial outbox to keep typed order <!-- feature:006 date:2026-10-07 -->
- Puppeteer MCP: closing a window opened with `window.open` can detach the tool's page handle ("detached Frame"); relaunch with `launchOptions` on the next navigate <!-- feature:006 date:2026-10-07 -->
- Headless Chrome: after `window.open`, the opener tab is `hidden`, so `requestAnimationFrame` and `IntersectionObserver` callbacks stop there; run scroll/observer checks in a single-tab browser <!-- feature:006 date:2026-10-07 -->
- Scroll containers (`overflow-*-auto`) must be `relative` when they hold `sr-only` or other absolutely positioned content: otherwise that content's containing block is outside the scroller, it escapes the clipping and widens the page (the cache inspector's hidden "Actions" header made the page 653 px wide at 360 px) <!-- quick:003 date:2026-10-07 -->
- `next build` imports route modules in its own worker processes: server modules must not do I/O at import (the upload store emptied its temp folder on import and wiped a running server's files during a build). Do side effects lazily on first request <!-- feature:007 date:2026-10-07 -->
- Request bodies stream into Node route handlers with real backpressure (reading slowly slows the sender), but the first ~2 MB go into socket buffers instantly: XHR upload progress races ahead of what the server has. Base speed/ETA on server-confirmed bytes <!-- feature:007 date:2026-10-07 -->
- Resumable pieces: let a newer request for the same upload supersede an abandoned one; refusing it as "busy" made every pause cost two pieces <!-- feature:007 date:2026-10-07 -->
- Virtual scroll corrections must happen before paint: measure rows and set `scrollTop` in `useLayoutEffect`, grow the spacer imperatively first (the browser clamps `scrollTop` to the old height), and turn off native scroll anchoring with `overflow-anchor: none` or it corrects a second time <!-- feature:008 date:2026-10-07 -->
- Don't observe every virtual row with one ResizeObserver and re-render from its callback: adding same-depth rows during delivery raises "ResizeObserver loop completed with undelivered notifications". Measure rendered rows in the layout effect; observe only the scroll box; re-sync on `document.fonts` `loadingdone` <!-- feature:008 date:2026-10-07 -->
- React `<Profiler>` `onRender` doesn't fire in production builds, so render timings shown in demos must be measured from the triggering event to the list's layout effect (after a forced layout), not from Profiler <!-- feature:008 date:2026-10-07 -->
- Test scripts that query `input[type=search]` hit the sidebar's "Filter practices" box first; scope demo queries to `section[aria-label="Live demo"]` <!-- feature:008 date:2026-10-07 -->
- The shadcn `destructive` button variant (red text on a 10% red tint) is only 4.1:1 in light mode; inside dialogs add `DESTRUCTIVE_TEXT` from `accessible-modal/modal.tsx` (token `color-mix`, 8:1 light / 4.7:1 dark) rather than editing `ui/button.tsx` <!-- feature:009 date:2026-10-07 -->
- axe-core's color-contrast silently skipped the buttons inside the hand-built (portal, animated) dialog: no pass, violation or incomplete entry. Check contrast of dialog content by computing it from computed styles, not by axe alone <!-- feature:009 date:2026-10-07 -->
- Headless Chrome uses overlay scrollbars (`innerWidth === clientWidth`) even with `--disable-features=OverlayScrollbar`, so layout-shift checks for scrollbar removal can't be reproduced headless; verify the `scrollbar-gutter` path by inspection or in a headed browser <!-- feature:009 date:2026-10-07 -->
- Return focus after a dialog one frame after closing starts, and let callers remove the opener synchronously (`flushSync`) when they act on the result; otherwise focus is sent to a button that disappears a moment later and drops to the body <!-- feature:009 date:2026-10-07 -->
- The Puppeteer MCP has no real keyboard: dispatched `Tab` keydowns don't move focus, so tests must emulate sequential focus navigation (next focusable in document order, skipping `[inert]`) whenever the page doesn't `preventDefault` <!-- feature:009 date:2026-10-07 -->
- The shared `useQuery` result's `error` is `null` (not `undefined`) before a result arrives; use `status !== "loading"` to know a query has settled <!-- feature:010 date:2026-10-07 -->
- Grid children default to `min-width: auto`: one long unbreakable line (a `truncate` span of component names) widened the page to 6,493 px at 360 px. Give grid items holding truncated or long text `min-w-0` <!-- feature:010 date:2026-10-07 -->
- Puppeteer: `el.blur()`/`focus()` don't fire focus events when the headless page lacks window focus (`document.hasFocus()` false); dispatch `focusout`/`focusin` to test blur handlers. Dispatched `input` events aren't processed as discrete, so pause before the next event that reads that state <!-- feature:010 date:2026-10-07 -->
- Background flashes (Web Animations on `background-color`) can fail axe contrast while they run; flash a ring (`box-shadow`) or run audits after animations end <!-- feature:010 date:2026-10-07 -->
- Claude in Chrome test tabs report `visibilityState: "hidden"`: `requestAnimationFrame` and CSS transitions pause and timers are throttled until long scripts time out. Use the Puppeteer MCP (visible page) for timing, frame-based or animation checks <!-- feature:010 date:2026-10-07 -->
- `useSearchParams` in a Client Component on a prerendered route needs a `<Suspense>` boundary; dev renders on demand and doesn't show the problem, only `pnpm build` does. Keep step/filter state in the address with `history.pushState`/`replaceState` (Next 16 keeps `useSearchParams` in sync) instead of `router.push` <!-- feature:011 date:2026-10-07 -->
- Puppeteer MCP `puppeteer_fill` inserts its text as the value (a `\t` becomes a literal tab), it doesn't press keys; keyboard-only checks still need emulated sequential focus. `history.length` caps at 50 in a long-lived test browser, so count `pushState`/`replaceState` calls (wrap them) to prove "no extra history entry" <!-- feature:011 date:2026-10-08 -->
- Base UI radio groups move focus with arrow keys and select on focus only after their own keyboard handling; dispatched `ArrowRight` moves focus without selecting, so verify radio choice with Space (click) when real keys aren't available <!-- feature:011 date:2026-10-08 -->
- Claude Code agent worktrees live in `.claude/worktrees/` inside the repo; without ignoring `.claude/**` in ESLint and `tsconfig.json` `exclude`, the main checkout's lint and typecheck scan every agent's in-progress copy <!-- feature:011 date:2026-10-08 -->
- Over HTTP/1.1 (`next dev` and `next start`) the browser allows ~6 connections per host: a stats request polled while six images are in flight queues behind them, so the counters read 0 for the whole latency. Open an SSE stream before the loads start (it keeps its connection) <!-- feature:012 date:2026-10-08 -->
- Browsers keep downloading `<img>`s removed from the DOM; when a view or run ends, clear `srcset`/`src` of unfinished images (`img.srcset = ""`), or the old requests hold the connections the next view needs. Clearing them aborts the request (the route handler's `request.signal` fires) <!-- feature:012 date:2026-10-08 -->
- Chrome scores layout shifts only for what is inside the window viewport: a gallery below the fold reports 0 even while it jumps. Scroll the measured area into view in tests <!-- feature:012 date:2026-10-08 -->
- IntersectionObserver `rootMargin` only grows the root: with the default (viewport) root, a scroll container still clips its children, so nothing preloads below its fold. Use the scroller as `root` <!-- feature:012 date:2026-10-08 -->
- A per-element dwell timer doesn't skip fast scrolls (a ~1000 px preload band is crossed in ~300 ms); to skip what the user flies past, start loads only once scrolling has paused <!-- feature:012 date:2026-10-08 -->
- `@next/next/no-img-element` warns on raw `<img>`; practices that hand-build image loading disable it per file with a reason instead of switching to `next/image` <!-- feature:012 date:2026-10-08 -->
- A fresh cache hit should skip the debounce: debounce only saves requests, and a hit sends none; checking the cache after the timer made going back to a cached query wait ~350 ms for nothing. Stale (SWR) entries should still wait, or each keystroke starts a refresh <!-- feature:013 date:2026-10-08 -->
- Abort alone hides the out-of-order bug in demos (aborted `fetch`es never resolve), so a "no stale guard" comparison must also switch abort off to reproduce it <!-- feature:013 date:2026-10-08 -->
- Reading `searchParams` in a practice page makes the route dynamic (ƒ in the build output); fine for the playground, but a static page would need `useSearchParams` under Suspense instead <!-- feature:013 date:2026-10-08 -->
- The shadcn `Table` component wraps `<table>` in its own `overflow-x-auto` div, which becomes the scroll container for both axes: a sticky header inside your own `max-h overflow-auto` box then sticks to the inner div and never sticks. For scrollable grids use the Table parts (`TableHeader`, `TableRow`, `TableHead`, `TableCell`) inside your own `<table>` <!-- feature:014 date:2026-10-08 -->
- A scroll box made with `overflow-auto` only clips absolutely positioned descendants if it (or something inside it) is their containing block: Tailwind `sr-only` is `position: absolute`, so sr-only text inside table cells escaped a non-positioned scroller and widened the whole page to the table's width at 360 px. Give such scrollers `relative` (add `isolate` when they hold a sticky header, so its z-index can't paint over the app bar) <!-- feature:014 date:2026-10-08 -->
- Headless Chrome via the Puppeteer MCP doesn't focus the page, so `focus`/`focusin`/`focusout` never fire even though `.focus()` moves `document.activeElement`; logic that tracks "focus is inside" with focus events alone passes in a real browser but not in those tests (and removing a focused element fires blur in real browsers). Also treat a keydown inside the widget as proof of focus, and drive real input with a Puppeteer script (`page.mouse`, `page.keyboard`) from the MCP's own `node_modules` when pointer drags or native key behavior matter <!-- feature:014 date:2026-10-08 -->
- An uncontrolled input re-keyed on a value (`key={page}` + `defaultValue`) remounts after each change: test scripts must re-query it instead of holding an element handle ("Node is detached") <!-- feature:014 date:2026-10-08 -->
- React's `<Profiler onRender>` doesn't run in production builds unless the app is built with `next build --profile` (React profiling build), which would slow every page; time renders in page code (event → first layout effect) when numbers must come from a production build <!-- feature:015 date:2026-10-08 -->
- A memoized subtree only skips when every prop is stable: one inline handler (`onSort={handleSort}` defined as a plain function in the parent) or a changing flag prop (`stale`) made a `memo` board re-render all 20,000 rows on every keystroke, which also silently cancelled `useDeferredValue`. Wrap handlers passed to memoized children in `useCallback` and keep cues like "updating…" on a wrapper element <!-- feature:015 date:2026-10-08 -->
- Measuring keystroke → paint with `requestAnimationFrame` + a `MessageChannel`/`setTimeout` callback over-counts when long work (e.g. a background React commit) is queued right after the frame; React's scheduler also uses `MessageChannel`. Stop at the `requestAnimationFrame` callback, or use the Event Timing API for real user events <!-- feature:015 date:2026-10-08 -->
- Puppeteer `$$eval` over ~50,000 elements throws "Maximum call stack size exceeded" (it spreads the handles); count inside `page.evaluate` instead <!-- feature:015 date:2026-10-08 -->
- `text-warning` (amber) fails WCAG contrast on light backgrounds; darken it in light mode with `text-[color-mix(in_oklch,var(--warning),black_40%)] dark:text-warning`, as practice 9 does for destructive text <!-- feature:015 date:2026-10-08 -->
